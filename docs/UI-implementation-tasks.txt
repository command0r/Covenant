TASK 01 — UI shell and appliance packaging
Dependencies: none.

Create a standalone Blazor WASM UI project. Build and embed its production assets
in Covenant.Host using ADR-0004. Serve the UI through the existing appliance;
retain the inference and admin APIs. Provide reliable nested-route reloads,
correct MIME types and WASM loading from the published artifact.

Port the shared shell, navigation, colour/type tokens, dark/light themes and
locally bundled fonts. Record font licences/provenance. Use shared components
for statuses, buttons, drawers, request facts and errors. No external CDNs.

Implement Connect/disconnect against the real admin API. Keep admin credentials
separate from application credentials. An application key stays in UI memory;
never persist it, prompts or responses in localStorage. Preserve the established
tab-scoped admin-token behaviour, clear it on disconnect, and never display/log
secrets. Remove seeded keys and identity claims. Identity is server-resolved.

Use one application state service for status, pause state and freshness across
navigation. Read real status updates, handle reconnect/401/staleness, and render
mutation failures without falsely claiming success. Disconnecting the console
does not pause Covenant. Data pages must not remain falsely authenticated.

Acceptance:
- Published single appliance serves the UI and assets without a separate server.
- Invalid token, disconnect, API outage and reconnect have correct visible states.
- Pause/resume uses POST /admin/kill-switch and stays consistent across pages.
- No fixture runtime, canned results or external font requests ship.
- Keyboard focus, labels, drawer close/Escape and focus restoration work.

TASK 02 — Stable request identity and exact evidence lookup
Dependencies: none; finish before wiring Playground evidence.

Choose and document one server-generated request correlation ID, created before
pipeline execution and returned even for governed refusals. Propagate it through
the canonical context, buffered responses, streaming response headers and audit.
Keep the existing audit-record identity if useful; define the mapping explicitly.
Do not trust a caller-supplied ID as unique or use timestamps to join records.

Add an admin-authenticated exact lookup API. The UI needs pending/not-yet-found,
found, unavailable/error and retry behaviour. Do not claim an audit write failed
merely because a bounded lookup timed out. Define lookup retention/snapshot
limits explicitly; full historical search is outside this task.

Add explicit audit metadata needed by these screens: classification evaluated
state, structured final outcome/denial kind, selected versus attempted versus
served model, and stopping stage where actually known. Keep measured stage
timings deferred. Never infer a complete measured trace from a reason string.
Preserve the restrictive default classification used for enforcement.

IMPORTANT: adding fields can change serialized bytes used by audit hashing.
Document a versioned/backward-compatible approach before implementation. Existing
logs and anchors must still verify without rewriting history. Legacy missing
fields display 'Not recorded', not fabricated facts. Check audit enqueue on client
cancellation: cancellation must not silently prevent the required audit record.
Define what happens to malformed requests rejected before canonical execution.

Acceptance:
- Concurrent requests, identical prompts and equal timestamps resolve correctly.
- Allow, auth denial, policy denial, pause, missing adapter, rate limit, upstream
  failure and cancellation carry the right identity/outcome wherever supported.
- Mid-stream failure retains transport HTTP 200 but final outcome is failure.
- Existing audit fixtures, anchors and ledger replay still verify correctly.
- Lookup is admin-only, bounded and never exposes unconfigured prompt content.

TASK 03 — Honest usage and estimated cost
Dependencies: coordinate audit schema with 02.

Preserve the distinction between unreported token usage and a real zero through
adapter, attribution, audit, API and UI. The current provider adapter replaces
missing counts with zero. Do not copy that ambiguity into the new screens.
Use explicit availability metadata or a compatible nullable representation.

Show 'Estimated provider cost' using configured prices and reported usage.
Show 'Not reported' for unknown billable usage. A refused request with no call
can legitimately show zero; a failed or cancelled provider call may not.
Local zero-priced inference is not free infrastructure.

Define and document a fail-closed accounting response to unpriced/unknown usage;
do not silently let unknown billable calls escape budget enforcement. Keep the
decision narrow, test it, and expose any resulting uncertainty or blocking state.
Maintain pre-call threshold semantics and explain concurrent overshoot. Do not
claim that this budget is a guaranteed provider invoice ceiling.

Acceptance:
- Tests cover complete, partial and missing usage, local zero price, no call,
  cache hit, interrupted stream and provider failure.
- Unknown cost cannot become a false $0 or false saving in any aggregate.
- Ledger replay and old records remain compatible with the chosen representation.

TASK 04 — Real Playground and presentation mode
Dependencies: 01, 02, 03.

Reproduce Main.dc.html's normal and presentation layouts with real API calls.
Presets A–D populate inputs only. The actual pipeline decides the outcome.
Use an application key with POST /v1/chat/completions, never the admin token or
a direct provider call. Support buffered and streaming responses.

Start empty; freeze a submitted request snapshot. Editing the form cannot
relabel its result. Prevent overlapping runs for this first version. Use the
server correlation ID, show asynchronous audit arrival with bounded retries,
and open the exact request in Requests. Add that same navigation action to the
presentation-mode evidence drawer, not just normal mode.

Capture errors from both transport and stream termination. Cancellation means
'stopped waiting/incomplete' where appropriate, never a guarantee of rollback
or zero charge. Use the real model catalog and allow explicit test overrides
without suggesting that selecting a model grants permission.

Correct a residual design issue: a route selected before a pause refusal or a
cache hit is not a model actually attempted. Display Selected model separately
from Provider attempted/Served model using observed backend facts.

Scenario D needs a fresh value on every run or verified disabled caching. The
system's pause scope remains new provider calls; cache hits and in-flight work
are not retroactively stopped. No invented pipeline timings or checks.

Acceptance:
- A succeeds; B refuses the unapproved model without a provider call.
- C fails closed without local registration and succeeds locally when configured.
- D refuses while paused, then succeeds after resume, repeatedly.
- Empty key yields real auth failure and 'classification not evaluated'.
- At 1280x720 and 1920x1080, prompt, Run, result, model, cost and evidence action
  fit presentation mode without page scrolling; long output scrolls inside it.
- No prompts/responses or application keys persist after reload/disconnect.

TASK 06 — One real Ollama/Qwen connection
Dependencies: 02, 04; 01 for wizard UI.

Extend the existing Local:Endpoint/Local:ModelId OpenAI-compatible adapter rather
than introducing another inference path. Support one exact installed Qwen tag.
Do not guess the user's host or tag, pull models automatically or change Ollama's
network exposure. Keep endpoint/tag inputs explicit and configurable.

Add admin-authenticated, host-side probe and model discovery operations with
timeouts, response-size limits and an explicit operator-configured destination
allow-list. Validate scheme/host/port and redirects/resolution; this must not
become an arbitrary server-side URL fetcher. Allow intentionally approved local
addresses; localhost refers to Covenant's host/container, not the browser.
Never forward the Covenant admin/application token to Ollama. Provider secrets
remain server-side and are never returned to the browser.

Expose applied configuration and an operational model catalog distinguishing
configured, registered, permitted, last successful observation, latest failure
and stale/unknown reachability. GET /v1/models alone is not a health check.

Port the wizard gates: valid endpoint → successful probe → discovery → exact
single tag → route review → manual config/restart → read back applied config →
governed inference test. Generate safe configuration guidance without embedding
secrets. Runtime apply/edit is deferred. Make it explicit in the UI.

The governed test must use an application key through the same pipeline as
Playground. The current design lacks that key flow: reuse the in-memory key or
ask for one; never treat admin sign-in as inference authorization. Link its real
request/evidence just like any other Playground request.

Fix the residual stale-success problem: after a successful test, a later failed
test must update shared health to failed/degraded. Preserve last success time,
but don't leave the header green. A paused test is not proof the provider is
unreachable. Draft endpoint changes invalidate draft probe results; they must
not silently change or erase the applied running configuration.

Provide explicit local-only startup configuration without requiring a cloud
key. Define routes deliberately; do not quietly reroute configured cloud traffic
or relax sensitive-data policy. Missing/invalid required configuration remains
fail-closed. Record an ADR for new startup/routing mode semantics before code.

Acceptance:
- Mock contract tests cover reachable/refused/timeout/empty discovery/tag mismatch,
  unauthorized destinations, redirects, stale results and response failures.
- A real smoke test with Alex's actual Ollama/tag proves buffered and streaming
  inference, audit correlation, and no cloud fallback for protected content.
- Failed probe blocks progression; changing endpoint invalidates its draft checks.
- Applied config is read back; a checkbox is never proof of registration.
- Successful test followed by failure updates all pages consistently.
- Local-only mode starts without cloud secrets; incomplete mode configuration fails.
- Optional Open WebUI instructions use Covenant /v1 and an application key.

Settings: read-only applied values; isolate archive/reset in Maintenance with

reset as the fix for a reached budget or silently clear evidence for the demo.

Acceptance:
- Pages agree on current environment, pause, health, counts and accounting scope.
- Failed verification, stale data, unknown usage and missing configuration are
  represented accurately, not as normal green states.
- Archive/reset retains old evidence and behaves exactly as described.
- No destructive maintenance is invoked by normal navigation or scenario selection.
